# Mediacore 创作首页：一次性 UI 原型

**问题：磨砂玻璃、圆角、简洁的视觉语言，配合哪种信息层级，最适合 Mediacore 的日常创作？**

当前结论：待用户比较。设计建议以 A 为日常首页基线，B 和 C 用来比较灵感权重与工作台密度；没有任何方案被认定为已接受，也没有部署到生产。

## 预览

在本原型分支的 `web` 目录执行 `bun run prototype:creation`。依赖使用现有 Bun 锁文件；新检出时先 `bun install --frozen-lockfile`。

- `http://127.0.0.1:5176/?variant=A`：雾白工作室，完整侧栏、居中输入、下方灵感。
- `http://127.0.0.1:5176/?variant=B`：灵感桌面，收紧导航、大幅案例与右侧输入并列。
- `http://127.0.0.1:5176/?variant=C`：暗场导演台，左侧创作控制、右侧镜头预览。

底部箭头或键盘左右键切换。输入框、下拉选择及对话框获得焦点时不拦截方向键。右上角支持明暗主题；底部“演示状态”展示当前完整状态。切换布局保留当前输入，刷新清空原型操作。

## 功能理解与设计依据

已阅读并对照线上首页：`pages/create/index.tsx`、`creation-workspace.tsx`、`creation-agent-entry.tsx`、`creation-workspace-empty.tsx`、`creation-types.ts`、`creation-references.ts`、`lib/inspirations/catalog.ts`、`components/layout/workspace-sidebar-nav.tsx`、现有路由与账号外壳。

| 现有能力 | 用户意义 | 本次设计处理 |
| --- | --- | --- |
| 文本 / 图片 / 视频 | 按产出类型选择创作流程，模型参数与参考能力不同 | 常驻模式选择，类型切换后更换模型及设置；正式适配仍消费原模型能力配置 |
| Agent | 在已保存画布中结合上下文、素材和技能开展协作 | 单独呈现新建 / 继续画布入口，保留审批说明，不假装是普通模型 |
| 灵感 | 浏览案例、把既有提示词带入创作 | A 放在输入下方；B/C 与输入并列。选择只填提示词，不自动生成 |
| 参考内容 | 用图片、视频、音频或文件约束生成，依模式与模型能力限制 | 添加入口及缩略图轨道保留；本地文件仅使用内存对象 URL |
| 技能 | 引用可复用的创作指引，不能当成模型或参考图片 | 独立 @ 技能入口与标签 |
| 模型与积分 | 模型决定能力，积分帮助用户预判消费 | 一个 4aion 下的模型列表；名称下方显示示例积分，选中勾在右侧；发送处显示本次消耗 |
| 历史对话 | 找回本页创作上下文 | 页面右上角保留入口 |
| 创作历史 | 跨页面的任务状态、记录与结果 | 导航保留独立入口，避免和历史对话混为一谈 |
| 短剧制作 / 自由画布 | 前者按项目组织流程，后者按节点自由组织内容 | 保留两个明确入口，不合并业务流程 |
| 专属生成工作台 / 资产 / 技能库 | 深度操作与复用材料 | 原入口保留，首页不复制这些完整模块 |
| 账户、容量、积分、公告 | 工作空间管理与运营信息 | 降低视觉权重，保留可发现入口；不恢复右上角更新日志 |
| 结果下载、重试/调整、画布接续 | 从单次生成进入持续创作 | 结果弹窗只演示操作位置，正式版继续复用原有会话、资源与任务链 |

玻璃用于区分导航、输入面板与浮层；正文使用稳定对比，图片保持原色。低饱和鼠尾草绿作为建议强调色，输入优先于装饰。没有增加仪表盘指标、新队列、账务、后端或 AI 网关。

## 边界与证据

- 位于独立 `prototype/mediacore-creation-glass` 分支；宿主是原有 `/` 与 `/create` 路由。既有路由、鉴权及数据获取保留，只在 DEV 且带 `variant` 时替换展示子树和外壳。
- 专用 Vite 配置拦截全部 `/api/` 请求，提供匿名启动只读夹具；任何写请求返回 405，不连接线上后端。原型状态只存在 React 内存中。原生宿主仍可能初始化这个独立 localhost origin 的偏好缓存。
- 模型名称、参数、余额、历史及结果均为布局示例，不是线上完整模型目录或有效报价；不得拿它们覆盖线上配置。
- 复用仓库原有灵感封面和提示词，不将其表述为本次生成结果；来源信息保留。
- 模式、模型、参数、参考选择、技能引用、历史、示例结果、主题和方案切换可交互。其余页面入口显示现有用途与目标路由，未重做那些页面。
- `bun run typecheck` 通过。Chrome 已查看 A/B/C，检查灵感填充、Agent 独立入口、示例结果、参考回填和窄屏参数定位。没有新增测试套件，也没有进行业务集成或真实生成验证。
- 用户尚未决定最终方向。后续只把接受的视觉决策落实到真实组件；原型和切换器继续留在本分支，不能直接合入生产。
