# Mediacore 多用户创作平台正式规格

本文件记录已确认的产品目标。唯一执行入口是[执行方案](mediacore-execution-plan.md)：原生验证 → 现有配置 → 必要局部调整，不自研缺失能力。需求存在不等于需要新开发，也不代表已经实现；不能通过现有机制满足的目标进入待决清单。独立原型已完成并选定 A「忠实磨砂」，用户已授权按当前票实施及 Subagent 并行开发。

## Problem Statement

用户需要将现有开源画布发展为可在服务器上运营的独立 Mediacore 平台，让多个用户安全地管理私有工程并使用平台提供的 AI 创作能力。当前基线虽已有用户、渠道、模型、任务和账务能力，但尚不能据此认定 4aion 协议兼容、积分收费准确、任务恢复不会重复消费，或服务器已达到目标容量。

用户还需要完整的 Mediacore 品牌与玻璃风格，覆盖主界面以外的认证、设置、弹窗、菜单、节点及管理端；保留现有组件、排版和位置，避免因换肤改变熟悉的操作。旧选型未投入生产，只作为视觉和成熟能力参考，无数据迁移需求。

## Solution

复用现有 React 画布、Go 业务后端、数据库、任务执行和积分机制，通过已有渠道配置与现成协议插件接入兼容的 4aion 模型。普通用户使用 Mediacore 积分，平台管理员统一管理用户、渠道、密钥、模型和成本倍率。所有现有创作类别都在覆盖范围内，但具体模型必须取得兼容性与计费证据后才启用。

以现有任务和积分机制验证以下产品目标：用户扣费受事前费用授权上限保护，超额由平台承担；最终确认无法交付的媒体任务释放或退还用户积分。不明确的供应商结果保留原任务与冻结积分，避免自动重发。Agent 媒体任务按清单与预算整批确认，独立任务失败不阻止其他独立任务，依赖失败结果的任务暂停。

部署验收后开放邮箱注册，新账号初始零积分；验证邮箱后独立设置密码，支持邮箱找回，登录固定保持七天。首期通过管理员发放积分及兑换码补充额度，真实支付暂未开放。每用户独立管理存储配额，积分归零不删除素材。主动创建的只读分享默认七天到期、可撤销，沿用原设计展示最新工程的节点内容、提示词、生成参数和媒体，不公开 Agent 聊天。

采用用户选定的 A「忠实磨砂」，以淡蓝紫环境光、半透明表面、高光边界与轻阴影统一浅色、深色和跟随系统主题。后续沿现有共享主题与组件完成全站覆盖，保持媒体清晰和画布操作性能。首期验收十人同时编辑；全平台最多三个未结束的供应商媒体生成任务，每用户最多一个，其余排队，普通 Agent 文字对话单独限流。部署与真实模型测试在后续获得相应授权后进行。

## User Stories

1. 作为访客，我希望所有自有页面、默认文案与发布入口都使用 Mediacore，以便识别同一个产品。
2. 作为新用户，我希望使用邮箱注册并验证验证码，以便确认账号归属。
3. 作为新用户，我希望验证后独立进入设置密码步骤，以便清楚了解当前需要完成的操作。
4. 作为新用户，我希望验证码过期、重发或重复提交得到明确反馈，以便安全完成注册。
5. 作为用户，我希望通过邮箱找回密码，以便恢复账号访问。
6. 作为用户，我希望登录后固定七天内保持会话，以便减少重复登录。
7. 作为用户，我希望退出或安全性操作后相应会话及时失效，以便保护账号。
8. 作为用户，我希望工程、素材、任务与积分属于自己的账号，以便私有数据不被其他用户访问。
9. 作为用户，我希望切换账号后旧缓存和旧请求不会显示前一用户的数据，以便避免混淆与泄露。
10. 作为用户，我希望分享链接仅按其明确授权范围访问资源，以便安全分享作品。
11. 作为用户，我希望删除工程后所有工程入口都反映删除结果，以便不会再次打开已删除的工程。
12. 作为用户，我希望直接选择平台提供的模型，以便无需配置个人 API Key。
13. 作为用户，我希望模型名称只显示模型名，以便快速选择。
14. 作为用户，我希望只看到已启用且通过验收的能力，以便不会把目录中发现的模型误认为可用模型。
15. 作为用户，我希望现有文本与 Agent 创作入口接入平台模型，以便延续现有工作方式。
16. 作为用户，我希望 Agent 的工具与媒体生成使用同一套权限和积分规则，以便消费行为一致。
17. 作为用户，我希望图片生成和编辑支持模型允许的参考图、蒙版及规格，以便完成现有创作流程。
18. 作为用户，我希望视频生成支持模型允许的文本、首尾帧与多模态参考，以便延续现有视频能力。
19. 作为用户，我希望音频生成与转写在现有入口可用，以便继续配音、字幕和相关创作。
20. 作为用户，我希望任务排队和生成状态可持续查询，以便了解任务进展。
21. 作为用户，我希望刷新、断网或服务重启后恢复原任务，以便不会丢失进展或重新付费生成。
22. 作为用户，我希望连续点击或重试同一次提交返回同一个任务，以便避免重复消费。
23. 作为用户，我希望余额不足时在提交路径得到明确提示且不触发供应商请求，以便控制支出。
24. 作为用户，我希望供应商是否受理尚不明确时看到待核对状态，以便理解冻结额度的原因。
25. 作为用户，我希望停止操作如实反馈供应商取消结果，以便不会把本地停止误认为已取消和退款。
26. 作为用户，我希望生成结果保存到平台资源中，以便供应商临时链接过期后仍可访问。
27. 作为用户，我希望结果保存失败时只重试保存，以便不会再次生成或重复扣费。
28. 作为用户，我希望查看可用积分、冻结与消费记录，以便了解额度去向。
29. 作为用户，我希望按照订单创建时的价格规则结算，以便管理员改价不改变已有订单。
30. 作为用户，我希望确认失败后的积分按规则释放，并且不会重复退款，以便账目可靠。
31. 作为用户，我希望通过兑换码获得积分，以便在真实支付尚未开放时补充额度。
32. 作为用户，我希望充值设计明确标示暂未开放，以便不会误认为已经付款或获得积分。
33. 作为平台管理员，我希望管理用户和受控地发放积分，以便开展首期运营。
34. 作为平台管理员，我希望发行、停用和核对兑换码，以便防止重复领取或并发超额兑换。
35. 作为平台管理员，我希望安全管理渠道与密钥，以便普通用户和浏览器无法读取供应商凭据。
36. 作为平台管理员，我希望复用模型发现、逻辑模型和协议配置，以便降低接入与维护成本。
37. 作为平台管理员，我希望逐模型记录协议、规格、成本与验收状态，以便控制模型开放范围。
38. 作为平台管理员，我希望按已确认的 4aion 成本基准乘统一倍率定价，以便统一管理用户售价。
39. 作为平台管理员，我希望缺失可信价格或用量时阻止收费启用或进入核对，以便不会按零成本放行。
40. 作为平台管理员，我希望成本目录变更可审阅、版本化和回退，以便避免误改在途订单。
41. 作为平台管理员，我希望关联内部任务、供应商请求和积分流水，以便核对差异与处理异常。
42. 作为平台管理员，我希望人工调整与核对操作有审计记录，以便追溯处理责任。
43. 作为用户，我希望浅色、深色与跟随系统都采用已选定的 A「忠实磨砂」风格，以便获得一致的视觉体验。
44. 作为用户，我希望设置、表格、菜单、弹窗和节点内容足够清晰，以便密集信息也容易阅读。
45. 作为用户，我希望换肤后组件位置、布局和操作路径保持一致，以便无需重新学习。
46. 作为用户，我希望主题色、字号等已有外观设置继续生效，以便保留个人偏好。
47. 作为用户，我希望空素材节点保留原 Icon、媒体内容清晰且生成与错误状态可辨认，以便准确理解节点状态。
48. 作为用户，我希望减少动态效果设置受到尊重，以便舒适使用界面。
49. 作为用户，我希望工程编辑与任务生成不会因增加玻璃效果而明显变慢，以便稳定创作。
50. 作为运营者，我希望验收十人同时编辑与三个生成任务同时执行、其余排队的场景，以便了解首期容量。
51. 作为运营者，我希望发布 Mediacore 自有且版本一致的前端、后端与 Agent，以便避免自动更新覆盖定制。
52. 作为运营者，我希望首管理员初始化、邮件、密钥、数据库与素材备份经过验证，以便安全运营与恢复。
53. 作为运营者，我希望观察队列、冻结待核对、渠道失败和存储增长，以便及时发现运营问题。
54. 作为维护者，我希望优先复用已有能力、配置和必要局部调整，缺失能力保留待决，以便降低升级和二次开发成本。
55. 作为维护者，我希望在独立 Mediacore Linear 项目追踪规格、依赖和证据，以便清楚区分规划、实现、部署与验收。
56. 作为用户，我希望主动创建的只读分享默认七天到期且可撤销，以便控制公开访问期限。
57. 作为用户，我希望存储配额与积分分别管理，以便余额归零不会导致素材消失。
58. 作为新用户，我希望公开邮箱注册后从零积分开始，并通过发放或兑换获得积分，以便明确额度来源。
59. 作为用户，我希望最终扣费不超过已授权上限，以便不会意外欠费。
60. 作为用户，我希望每人最多占用一个媒体生成名额，以便其他用户也能获得生成机会。
61. 作为用户，我希望 Agent 展示媒体任务清单与费用上限后由我确认整批，以便控制自动操作的消费范围。
62. 作为用户，我希望同批独立任务在其他任务失败时继续执行，以便不浪费已授权的工作。
63. 作为用户，我希望最终确认无法交付的媒体任务退还积分，以便不为拿不到的结果承担费用。
64. 作为用户，我希望分享延续原有画布展示内容，以便访客能查看提示词、生成参数与媒体，同时不公开 Agent 聊天。
65. 作为用户，我希望分享展示工程最新内容并在创建时得到明确提醒，以便理解后续修改也会对访客可见。

## Implementation Decisions

以下为产品规则与复用边界。

- **权威与复用。** 保留 React/TypeScript、现有画布渲染与状态体系、Go 业务后端、PostgreSQL、Redis 和独立 Node Agent。Go 后端统一掌握用户、资源归属、模型准入、任务和积分业务权限。先验证原生行为，再使用现有配置及现成插件，最后做已确认的必要局部调整；不能覆盖的目标列为待决差异，不自研缺失能力。
- **数据边界。** 新工程独立部署和数据初始化，不迁移旧账号、余额、工程或任务，不删除旧参考资料。所有私有读写、任务轮询、媒体访问、Agent 工具与后台操作均验证身份和资源归属；分享由用户主动创建，只读、默认七天到期且可随时撤销，持有效链接者无需登录即可查看授权内容；工程其余内容保持私有。账号切换清理用户缓存并阻止旧异步响应回写。工程删除同步失效列表、直接打开与关联访问，物理资源清理沿用资源生命周期机制。
- **分享内容与版本。** 沿用原分享设计：保留节点展示内容、提示词、生成参数及节点媒体；Agent 聊天不公开，继续过滤密钥、内部存储/任务字段及未通过节点展示的参考数据。节点媒体可被持链接者读取或保存，不承诺隐藏下载按钮能防止下载。分享实时读取当前工程，不新增创建时快照；创建分享时明确提醒后续修改会在有效期内公开。七天默认到期、只读与随时撤销规则不变。
- **存储配额。** 每用户独立配额、管理员可调整；接近上限提示，达到上限限制新增上传和生成，已有素材仍可查看、下载和按既有引用规则删除。积分归零不触发自动删除；具体容量在服务器资源确定后配置。
- **认证。** 部署验收后开放邮箱注册，新账号初始零积分，通过管理员发放或兑换码获得积分，首期不新增注册邀请码。邮箱注册、验证码、独立设置密码、邮箱找回组成完整流程。验证码验证凭据具有用途、账号与期限约束，单次消费且防止并发重放；沿用发送频率与尝试次数保护。固定七天登录由服务端会话和 Cookie 一致约束，不因活动静默延长；退出撤销相应会话，密码重置撤销旧会话。实际 Cookie、跨域、代理和 HTTPS 配置在部署环境验收。
- **平台供给。** 管理员维护加密渠道密钥、模型发现、逻辑模型和启用状态。普通用户无需个人 Key；后端同时禁止绕过平台供给的自带密钥入口。浏览器、用户响应、诊断日志与导出不暴露密钥。模型显示名和精确供应商 ID 分别保存，显示名不附解释。
- **逐模型合同。** 记录实际生效的协议适配、鉴权、操作类型、输入输出限制、规格、参考素材角色、计量规则、成本来源、限流与取消能力。发现模型不代表验收通过。覆盖现有 Agent、文本、图片、视频、音频、转写等创作类别；模型通过能力、权限、资源回存与账务验证后才启用。
- **协议兼容。** 使用现有声明式协议配置和现成插件；需要新多阶段流程的模型保留为兼容差异。核对实际被插件接管的请求，不能只修改未生效的旧适配器。文本与 Agent 分别验证流式响应、工具调用、多轮关联和用量；图片区分生成、编辑及实际报文；视频区分不同协议的参数与任务查询；转写只验证现成协议，不能覆盖时保留入口差异，不新增适配实现。
- **素材输入。** 默认复用平台存储与签名读取链接。需要供应商素材注册、专用存储或多模态绑定的模型，核对现成协议是否已覆盖鉴权、用户/账号范围及恢复；不能覆盖时保持未开放，不新增素材客户端或协调流程。预签名上传只携带其授权头，不向第三方地址泄漏平台 Bearer 密钥。
- **任务与重复提交。** 保留 PostgreSQL 持久任务、worker、租约、fencing 与 Redis 协调。目标是同次用户提交的重试不重复生成和冻结；核对原生接口行为，不预设增加操作键、数据表或新提交协议。内部账务幂等不证明供应商恰好一次受理；普通提交差异见 NIK-277。
- **恢复与取消。** 核对现有素材准备、提交、查询和结果回存检查点的覆盖。供应商可能已受理但响应丢失时保留原任务，查询可用的原请求或进入待核对，禁止自动重新生成。恢复 worker 不能绕过此规则。停止请求不等于取消成功；只有确认供应商结果后才终结任务并按合同结算或释放。已成功生成而回存失败只重试回存。轮询遵守供应商间隔和限流，不用无界重试。
- **批次失败。** 已授权批次中，独立任务在其他任务失败时继续，依赖失败结果的任务暂停；不自动重新发起失败的付费生成。已成功交付部分正常结算，未执行部分释放预留；暂停的依赖任务恢复前重新校验依赖和授权，不能沿用已经释放的额度。已提交但结果未知的任务继续待核对，不能作为未执行部分释放。
- **最终无法交付。** 供应商成功并收费，但经过结果回存恢复后最终确认素材已无法获取、无法交付时，由平台承担该媒体任务成本：未结算则释放该任务冻结，已结算则通过可审计退款流水退还已扣用户积分，重复恢复/核对不能重复退还。不以一次下载失败或仍未知的结果触发退款，不自动再发起付费生成；同批已交付任务仍正常结算。此决策见 ADR-0013。
- **计费合同。** 复用整数积分精度、原生成本价格档、倍率、冻结与账本。应计费用按订单快照成本单价与对应实际用量求和，再乘快照统一倍率与货币/积分换算，最后统一舍入；实际扣费同时遵守费用授权上限与最终无法交付的退款规则。区分输入、输出、缓存 token、时长、规格与按次用量；公开标价、账号/分组成本和最终供应商账单分别标识。
- **价格与异常。** 提交前明确费用授权上限并预留相应积分，保存授权范围、成本、规格、倍率、换算和规则版本快照。按实际用量计算应计费用，用户实际扣费取应计费用与已授权上限的较小值；超出部分记录平台差额，不形成负余额。保守估算和输出预算用于控制平台风险，不能替代用户授权。缺价、缺计量或缺关键用量不默认为零费用。未具备可信计价条件的模型不开放收费；已执行但结果不明确则保留冻结积分进入待核对。余额不足在供应商调用前拒绝。重复通知、恢复和人工处理不得重复冻结、结算或退款。
- **账务运营。** 统一倍率和成本更新只影响新订单；成本目录支持审阅、生效版本与配置回退。实际账单具备后按供应商请求/任务标识核对，差异可追踪，不能因更新价目追改旧用户订单。管理员发放、兑换、停用、核对和调整沿用账本且可审计；兑换码并发使用不能突破额度或次数。
- **Agent 授权。** 文字对话按所选模型计费，遵守费用授权上限。Agent 发起图片、视频、音频生成前展示任务清单与费用上限，用户一次确认整批，在明确授权范围内执行；新增任务或超出预算须再次确认。复用现有预算和审批能力，不恢复旧版四次请求硬上限。
- **支付边界。** 首期真实支付暂未开放，支付宝/微信切换和金额选择设计不得生成真实订单或显示付款成功。后续取得商户配置后单列支付合同及验收。旧版充值布局作为设计参考，不能据此改变本平台既有页面几何。
- **品牌。** 自有产品、项目、任务与规格均只使用 Mediacore；覆盖默认配置、Logo、图标、metadata、Agent 身份、认证、邮件、空态、异常、欢迎页、导出说明、恢复默认、帮助与自有发布入口。慢网、配置失败、缺图与重置不得闪现旧品牌。保留法定版权、许可证、真实第三方/模型名称与必要隐藏兼容标识，逐项记录兼容原因；不把上游支持链接当作 Mediacore 客服入口。
- **玻璃主题。** 使用现有 Mediacore 的淡蓝紫环境光、半透明表面、细高光边界和轻阴影。浅色、深色、跟随系统全部覆盖；密集内容提高表面不透明度。材质允许创作，但固定既有组件、布局、位置、控件尺寸、间距及默认字体度量；独立设置密码是已明确授权的流程例外。不得换组件库或借换肤重排页面。
- **A 材质参数。** 原型选定的默认基础/密集表面不透明度为浅色 64%/92%、深色 72%/94%，背景模糊 22px。基础表面用于导航和轻量外壳，密集表面用于节点内容、表格与浮层；沿现有语义 token 和控件主题落地，原型的全局强制覆盖不直接搬入产品。媒体内容不叠加模糊，既有主题色、字号、圆角和主题归属继续生效；不为统一材质改变画布与工作台的偏好隔离。不新增 API、数据表、主题服务或业务流程，B/C 不作为新产品选项。
- **样式落点与覆盖。** 语义 token、皮肤适配和共享控件先行，覆盖现存 AntD 与 Celadon/React Aria，再处理页面与节点特例。认证与验证步骤、工作台、画布、全部自有节点、Agent、工程、分镜/时间线、媒体工具、任务、设置、充值、后台、分享与异常页均纳入；浮层、portal、菜单、tooltip、drawer 和嵌套 modal 同样覆盖。验证默认、悬停、焦点、选中、禁用、加载、错误、空态。第三方插件统一可控的宿主与共享控件。
- **交互与性能。** 媒体不被玻璃滤镜覆盖；无素材时保留原 Icon。可操作控件和生成、停止、错误状态必须清晰。保留视口过滤、空间索引、LOD 和挂载预算，避免层层 blur 及对 blur 半径的连续动画；遵守减少动态效果偏好。主题色、字号等已有设置继续生效。
- **原型决定范围。** 用户已从 Astra 制作的三档原型中选定 A「忠实磨砂」，作为全站玻璃风格基准；参数与证据见[执行方案](mediacore-execution-plan.md#推进顺序)和 NIK-272。原型保持相同组件树、几何与模拟数据，不接付费模型或真实支付；选型不代表正式实现或全站业务验收。此前旧产品的 Agent 改位、折叠与历史消息细节不自动变成本项目新增交互需求。
- **部署与恢复。** 首期单业务后端实例，独立 PostgreSQL、Redis 和资源存储；前端网关、Go、Node Agent 与一次性迁移对应同一自有候选版本。镜像固定可追溯版本或 digest；上游自动更新及镜像回退改为自有发布链或关闭。受控创建首管理员，验证 HTTPS、CORS、可信代理、SMTP、存储及必要媒体运行时。数据库、对象数据和密钥加密根材料共同备份并演练恢复；镜像回退不等于数据库回退。
- **容量与可观测性。** 目标为十人同时编辑；全平台最多三个已提交供应商且尚未结束的图片、视频、音频生成任务，每用户最多占一个，超额排队。名额覆盖供应商实际生成等待期，不因本地 worker 暂时空闲释放；Agent 媒体工具同样受约束，普通 Agent 文字对话单独限流。记录编辑性能、保存延迟、队列等待、供应商耗时、未知冻结、回存失败、渠道错误、存储增长与邮件失败。容量目标尚未验证，不宣称现已具备；多副本扩容另行验证全局准入与共享状态。
- **交付组织。** 独立 Mediacore Linear 项目为唯一任务状态来源。按唯一执行方案和已修订 Linear 任务推进；全局主题等共享文件明确单一负责人，原生能力满足即验收，缺口不自动转为开发任务。规划、原型、源码验证、部署和用户验收分别留证。

## 能力差异处理

费用授权上限（NIK-276）、普通重复提交（NIK-277）、最终不可交付退款（NIK-279）均为待决差异。专用素材/转写、供应商在途名额、Agent 批次授权与失败依赖也需核对现成机制。上文保留的是用户目标，不能据此新建结算、协议或调度实现。差异及可复用选项统一在[执行方案](mediacore-execution-plan.md#待决差异)列出，处理状态以 Linear 为准；不默认用户接受未满足的收费和权限行为。

## Testing Decisions

- **主测试边界。** 沿用已确认方案，通过真实用户路由及已认证业务 API 验证业务行为，观察持久任务、资源与积分结果。外部 4aion 使用可控制的协议替身注入超时、受理后断连和重复响应；不为每个内部函数新增测试接口。少量价格舍入等纯计算边界可保留针对性单元测试。
- **复用基础。** 延续已有认证注册、密码重置、登录状态、用户资料会话、画布分享字段过滤与资源访问、主题启动与外观、任务持久化与媒体恢复、供应商恢复、账务授权、支付及音视频计价测试的结构。已有测试存在不等于已验证本规格；增加断言应证明新约束或回归风险，避免镜像实现细节。
- **认证和隔离。** 验证邮箱全流程、独立密码步骤、验证码期限/重放/并发、Cookie 与服务端七天边界、退出与重置撤销。A/B 用户交换工程、资源和任务标识，直接调用后台与个人渠道入口；覆盖换号缓存、并行标签页、旧请求响应、授权分享和删除后再次打开。
- **任务与账务。** 通过现有接口验证重复点击、跨用户提交、并发提交与响应丢失重试；余额不足无供应商调用；受理不明、429/5xx、worker 重启、取消不明、明确失败、回存失败、重复结算与退款。通过供应商调用计数、任务标识和积分流水证明无重复生成与扣款，不只断言界面文案。
- **计价与运营。** 覆盖各计量单位、缓存 token、精度与舍入边界、改价后的老订单、缺价/缺用量、实际成本核对，以及管理员发放和兑换码重放。必需参数未配置时不能开放收费；真实支付未开放不得创建付款成功记录。
- **模型与素材。** 先按协议 fixture 验证实际请求、鉴权、流式响应、Agent 工具关联、图片参考/蒙版、视频参考与查询、音频和转写结果、资源持久化。对现成支持的素材流程验证账号/用户范围、并发准备与恢复、预签名上传头；不兼容项记为差异。后续在明确模型、次数和总额预算下做真实调用验收；未通过模型不启用。
- **视觉与几何。** 相同桌面视口、数据、字体加载与缩放下对比基线和新皮肤的截图、DOM 几何、节点坐标、命中区及滚动边界；固定布局不漂移，阴影变化单独判断。逐一覆盖三种主题、两套控件、节点与浮层状态、字号/主题色设置、冷启动/配置失败/恢复默认。素材本身不得被模糊。
- **A 方案增量验证。** 继续使用真实路由及原有组件作为最高层验证边界，不新增内部测试接口。复用现有应用主题、自定义皮肤、认证主题、品牌启动回退、画布主题隔离及管理控件回归测试的适用部分；源码字符串断言不替代浏览器行为和视觉检查。每个换肤切片交付自己的真实入口、关键操作、浮层和三种主题证据；共享样式变更复核已完成入口，已被共享层满足的页面以验证交付，不逐页重写。原型证明材质选择及示例节点几何，未证明完整注册流程、后台导航壳、全节点覆盖或真实工程性能，这些仍在正式实施验收范围内。
- **性能与部署。** 同机同工程对比首次和再次打开、拖动/缩放帧耗时、主线程长任务、内存与保存延迟，包含有代表性的媒体节点。十人编辑与三任务生成验收分开记录排队和供应商耗时，不能以空画布代替。部署验证自有版本一致、管理员初始化、邮件与存储、任务重启恢复和备份恢复；健康检查不代替完整创作路径。
- **补充运营边界。** 验证分享七天到期、撤销与持链接匿名只读访问；账号初始零积分；存储达到配额时禁止新增而保留读取、下载和删除。费用高于预留时用户扣费不超过授权上限，平台差额可审计且余额不为负；媒体名额覆盖供应商等待期，全平台三、每用户一；Agent 新增任务或预算变化使原授权不再覆盖新增消费。
- **批次与分享补充验收。** 注入同批独立任务失败和依赖失败，分别验证继续与暂停、未执行额度释放、未知任务保留冻结；模拟供应商收费后最终不可交付，验证未结算释放/已结算退款各自幂等，其他成功任务账务不受影响。分享验证提示词/生成参数可见、Agent 聊天和敏感字段不可见、工程更新在分享中生效、到期或撤销后资源访问失效，以及创建时实时公开提醒。
- **完成证明。** 每个实现包提供行为证据、影响范围及失败/跳过项；源码检查、构建测试、真实模型验收、服务器部署和用户体验确认分别记录。当前规格仅规定未来验收，未执行产品测试或证明容量、兼容性和生产可用性。

- 首期真实支付宝/微信收款；自研缺失业务能力、新协议流程或迁入另一套系统。
- 未经专项验证的多副本服务、无限容量承诺与自动替换为上游发行版。
- 删除许可证和法定署名，或为了去品牌破坏必要的第三方与数据兼容标识。
