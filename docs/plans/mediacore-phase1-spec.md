# Mediacore：影策开源画布第一阶段简化规格

## Problem Statement

把现有影策开源画布部署到用户的 Linux 服务器，对外品牌改为 Mediacore，并接入 4aion。第一阶段最大限度使用成熟上游代码、功能、界面和业务策略，不重新开发或逐模块重新证明整套产品。

用户已撤回 35 票草案并确认本简化方案。本版本取代此前 78 条故事和全量验收要求；历史研究可按需查阅，不自动产生开发任务或上线前置条件。Linear 的 NIK-287 保留来源规格历史，实际一期执行范围以本版本及下列三张任务为准。

## Solution

第一阶段只保留三项工作：

1. **品牌替换（NIK-292）**：将对外名称、Logo、默认文案和自有链接改为 Mediacore；优先使用现有外观配置。保留必要署名和内部兼容标识，界面布局与交互不重做。
2. **4aion 接入（NIK-289）**：优先配置原有系统渠道、模型、密钥与价格。仅对证实不兼容的鉴权、参数、响应、视频查询或素材准备作局部修改。
3. **Linux 部署（NIK-293）**：合并前两项，沿用上游部署编排和依赖，配置公开注册、邮件、存储、积分和常规备份，走通基本使用流程。

品牌与渠道可以并行；最终部署依赖两项完成，环境准备可提前进行。旧功能矩阵、账号、积分和全量验收任务取消独立执行，原生功能继续保留。二期需求池保留，待一期交付后再评估。

## User Stories

1. 用户访问服务器上的 Mediacore，看到统一品牌并使用影策原有页面和操作方式。
2. 用户通过原生注册、登录和账号流程进入自己的创作空间。
3. 用户沿用现有画布、项目、素材、分镜、分享、剪辑和其他非 AI 功能，无需等待重新开发。
4. 用户直接选择平台提供的模型，通过 4aion 完成已有 AI 创作，普通用户不配置个人供应商渠道。
5. 用户使用原生积分和兑换码；首期通过现有外部收款渠道交付额度，不要求网站自动收款。
6. 用户能查看和下载生成结果，保存画布后可以重新打开。
7. 4aion 确认不支持的 AI 能力可暂时关闭并说明，原实现保留；未知能力列为待解决项。
8. 管理员通过现有后台管理账号、模型、积分及运营配置，并取得简短部署和备份说明。

## Implementation Decisions

- 固定影策基线为 `26dfb8d91bddf78ada93f7cba079368f1634db6d`（v1.6.7），沿用现有 fork 与独立工程分支，不覆盖旧工程。
- 先配置现成能力，再对具体差异作最小补丁。原生已满足的功能不改；不因“可以优化”而重构。
- 账号、会话、权限、分享、任务恢复、取消、积分结算、素材和编辑器沿用上游策略。只有实际接入或使用遇到具体问题时，才处理相关局部缺陷。
- 所有 AI 调用（包括 Agent、技能和插件）仅走 4aion，平台统一管理密钥和积分。优先用原生系统渠道、权限和功能开关实现，不新建网关。
- 4aion 确认缺失的能力可关闭，不以其他供应商或本地 AI 兜底。未取得资料或凭据不等于供应商不支持。FFmpeg 等普通媒体处理继续使用。
- 模型按保留能力选择代表型号，按实际账号有效成本配置价格，不要求接通整个模型目录。
- 保留原生公开注册和多用户机制；用现有配置控制媒体任务全局 3、每用户 1。10 人编辑是规模参考，不设为专项压测门槛，不据此宣称已验证容量。
- 前端、后端与 Agent 使用一致、可追溯的自有版本。保留其他服务和数据，配置常规备份；不单立灾难恢复或高可用工程。
- 并行执行者使用独立目录与分支，公共类型、配置和部署资源协调修改，合入一个候选。

## Testing Decisions

仅做实际改动相关的必要检查和基本使用验证，复用已有测试，不为未改动的原生功能另建验收项目。

部署后走一遍：注册/登录 → 创建和保存画布 → 发放或兑换积分 → 用已接通模型生成 → 查看和下载结果，核对画布持久化、产物和积分记录。检查真实页面中的品牌改动。

每类保留 AI 能力用代表模型确认接入；修改协议时检查相应成功和失败处理。可先用可控响应验证必要协议差异；真实调用需要已明确的模型、次数和预算。

不要求全量模块回归、19 类验收矩阵、系统性故障注入、全套账务审计、独立恢复演练或专项容量压测。实际修改影响到权限、密钥或扣费时，仍进行对应的针对性检查。

交付只需简述修改、实际检查结果、服务入口和剩余配置/关闭项。没有做过的验证不宣称通过，交由用户试用确认。

## Out of Scope

- 第一阶段新增产品能力，重设计界面，重写认证、网关、队列、账务、素材或编辑器。
- 把成熟上游已有功能再次拆为待开发模块。
- 为增加并行数而拆成 35 张票，或提前搭建通用测试和故障注入框架。
- 非 4aion 的 AI 调用、个人渠道绕行、本地 AI 兜底。
- 全模型接入、组织租户、团队实时协作、旧工程数据迁移和网站自动支付作为一期必备。
- 未明确预算的付费调用，未经确认的商业售价。
