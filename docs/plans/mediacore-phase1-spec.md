# Mediacore：影策开源画布第一阶段正式规格

## Problem Statement

用户需要把影策开源画布变成可在自有 Linux 服务器公开运营的 Mediacore，让多个用户独立管理创作工程、素材和任务，并通过平台提供的 AI 模型完成创作。用户希望最大限度复用影策已有的代码、功能、操作方式和业务策略，避免在第一阶段重写已有系统，或把新功能开发混进基础产品跑通工作。

当前固定上游已有账号、系统渠道、持久任务、素材、积分、兑换码及运营后台，但这些源码能力尚未在本工程验证。4aion 对各类创作操作的实际兼容性、完整媒体依赖、平台凭据隔离、费用闭环、服务器容量与备份恢复均不能仅凭页面或配置存在认定可用。默认品牌与发布来源也需要统一为 Mediacore。

## Solution

基于已建立的独立工程和上游固定基线，第一阶段先验证原生功能，再使用已有配置，最后针对证实的必要差距作局部调整。保留熟悉的界面布局和原生策略，跑通创作与运营完整流程；第二阶段才评估超出上游既有能力的扩展。

Mediacore 第一阶段开放注册，平台管理员统一管理 4aion 密钥、模型和积分。普通用户无需配置供应商渠道，以 Mediacore 积分消费。首期商业运营通过现有外部收款渠道配合管理员发放积分和兑换码完成；网站内自动支付不是首期必需。

所有 AI 调用仅走 4aion。每项保留的创作能力至少有一个经过验收的模型，按模型逐步开放。对确认无法由 4aion 支持的原生 AI 能力，允许暂时关闭后首期上线，保留实现、列明缺失证据和恢复条件，关闭项不记为通过；不得隐式切换其他供应商或本地推理。FFmpeg 等普通媒体处理继续复用。

用户可见品牌统一为 Mediacore，保留法定署名与必要内部兼容标识。Linux 部署需经过真实使用流程、用户隔离、账务、恢复和容量验收。首期容量目标为10人同时编辑、全平台最多3个未结束媒体生成任务、每用户最多1个，其余按原生队列处理。

## Implementation Decisions

- **基线与阶段。** 固定影策上游提交 `26dfb8d91bddf78ada93f7cba079368f1634db6d`（v1.6.7），使用既有fork中的独立分支。原生验证→已有配置→必要局部调整；不因发现代码可优化而扩大范围。新增产品能力留到第二阶段。
- **原生架构。** 保留React画布、Go业务后端、生产PostgreSQL与Redis、独立Agent运行时和现有部署编排。继续使用原有认证、资源、任务、权限、协议插件与积分账本，不新建替代系统。
- **业务默认值。** 注册与找回、会话、分享、取消/失败、冻结结算及界面布局均沿用原生策略，并用本规格的验收证明其适用性。登录期限、分享期限、初始赠额、收费上限或退款补贴等未在本轮决定，不继承旧项目自定义规则。
- **平台调用边界。** 管理员管理系统渠道和密钥；普通用户消费平台模型与积分，不配置个人渠道。所有AI请求包括Agent、技能、插件与外部工作流都受服务端边界约束，仅隐藏前端入口不算完成。供应商授予的上传/下载地址按其合同使用，普通媒体传输不等同额外AI供应商。
- **4aion适配。** 优先映射现有协议的地址、鉴权、模型能力和响应字段；确有差异时在既有provider、协议插件或素材准备边界做最小适配。逐项核对文本流及工具调用、图片生成/编辑、视频创建查询与参考素材、音频及字幕时间戳，不能根据模型名称或通用兼容标签宣称全部可用。
- **异步与素材。** 保留原有持久任务、供应商任务ID、SSE、资源保存和恢复流程。Seedance精确模型标识、素材项目/模型绑定、上传凭据与完成确认、轮询间隔按已核实合同验证；创建受理不明时先查询和核对原任务，不无条件重发。向预签名上传地址发送其指定上传头，不能转发平台供应商密钥。
- **能力例外。** 首期以每项保留能力至少一个通过验收的4aion模型为门槛。确认不支持的AI能力可以关闭并记录证据、用户提示、后端限制和恢复条件；未取得证据不等于已证明供应商不支持。关闭项不计通过。原生Whisper路径受唯一供应商决定限制，保持现有转写任务和字幕消费结构，先核实4aion合同，再局部适配或明确关闭。
- **原生编辑合同。** 保留时间线状态机、命令历史、任务化转写和统一渲染计划；补齐FFmpeg依赖，不重写编辑器或渲染引擎。遵循既有ADR关于编辑/预览/导出分层及媒体产出模型与选用模型分离的决定；Mediacore唯一供应商边界限定上游可插拔ASR的实际开放范围。
- **财务运营。** 首期使用管理员发放、兑换码和原生积分冻结/结算/异常核对。真实账户成本、积分换算、售价和模型开放配置留待提供；公开目录零价不能用作售价依据。不自动启用网站支付，也不因首期可用兑换码就删除原生支付实现。
- **多用户与管理。** 复用个人账号与项目归属的多用户基础、原生分享例外及管理权限。不把已有多用户误认为已具备组织租户或实时团队协作。公开前先受控创建首个管理员；使用原生验证、限流、条款和邮件机制。
- **品牌和发布。** 原生站点与助手外观配置优先，再补冷启动、降级和恢复默认等展示硬编码。统一自有界面、文案、图标、文档及发布入口；保留法定来源、第三方权利和必要协议/数据标识。自有前端、后端、Agent镜像版本来源一致且可追溯，核对更新器不会覆盖Mediacore版本。
- **部署与容量。** 使用用户指定Linux目标，部署前核对已有工作负载、端口与数据所有权；保留其他工程数据。媒体并发限制覆盖供应商尚未结束的任务，不能仅限制HTTP请求瞬时并发。文本对话复用并核对原生限流。10人编辑与3/1媒体并发是验收目标，尚非承诺容量。
- **持久化与接口。** 当前没有已决定的新数据库模型、API或公共测试接口。优先沿用现有业务合同；必要变化随具体任务论证、迁移与回归，避免为本规格预先引入新抽象。
- **追踪。** 本规格为本次新Linear项目的需求与验收基线。现有一期任务和二期池继续使用，状态和依赖只在Linear维护；研究报告提供固定基线证据，不代替运行结果。

## Testing Decisions

- **用户已确认的主边界。** 以真实用户流程和现有业务接口为最高层验证边界，观察项目、任务、资源、权限与账本结果。先以可控4aion响应验证成功、失败、超时及恢复，再在明确模型、次数和总预算后做真实调用。不新增专用内部测试API，不以实现函数调用或字符串存在作为业务通过证据。
- **原有基础。** 复用上游认证注册/条款/密码重置/会话测试，资源handler和跨用户访问测试，任务媒体/供应商恢复测试，兑换码与财务恢复测试，以及前端任务重放、文本流、品牌启动和外观测试。沿用现有Go、Bun及浏览器验证工具；既有质量流水线包含PostgreSQL、Redis和3D浏览器测试，但其存在不代表当前候选通过。部署所用PostgreSQL主版本也需覆盖，不能只依赖不同版本的CI结果。
- **功能矩阵。** 从19类原生能力逐项记录入口、实际行为、依赖、通过证据与例外：项目、画布、自由创作、工作台、Agent、剧本分镜、3D预演、素材、任务、时间线、分享、灵感、技能、插件、账号、积分、模型渠道、运营品牌、运维。上游待测试和文档不一致项用真实行为核实，不把愿景当已实现功能。
- **注册与隔离。** 测试真实注册/验证/找回/退出/账号切换及管理员初始化。A/B账号交换项目、资源、任务标识，调用普通与管理业务接口；验证读取、写入、删除、下载、Agent上下文和迟到请求的隔离。原生分享作为受控例外测试授权范围和撤销。
- **模型与出站。** 在既有供应商HTTP边界使用可控响应，检查鉴权、模型、参数、参考媒体、SSE、工具关联、异步ID和返回产物。验证普通用户、Agent、插件和自定义渠道无法绕过4aion及账务规则；已关闭能力在界面与服务端一致。检验供应商密钥不进入客户端、日志和导出。
- **恢复与财务。** 注入创建受理后断连、429/5xx、轮询中断、worker重启、重复响应、取消不明、下载失败等情景。以原任务ID、供应商调用计数、资源数量及账本条目证明恢复不重复生成/消费；核对原生失败返还、不明费用待核对和幂等结算，而不是只看提示文本。
- **商业流程。** 验证发放积分→兑换码领取→生成→结算→查询记录，包含重复/无效/停用码、余额不足、并发兑换/提交和错误定价。真实成本及用量未明确的模型不得凭零价目录作为收费验收通过。网站自动支付未启用时验证界面不误示支付成功。
- **媒体与编辑器。** 验证所有返回媒体保存、引用和下载，多图结果不丢失，素材引用删除保护。真实执行时间线编辑→导出→入库→下载。ASR开放前验证4aion输入格式、字幕内容和时间戳满足原消费结构；无法满足时检验关闭例外，不能用本地Whisper替代供应商验收。
- **品牌与界面。** 使用真实路由验证正常/首次/配置失败/重置状态，覆盖登录、创作、画布、弹窗、管理与分享等展示；沿用原生主题、布局和操作。源码检索辅助查遗漏，截图和可操作行为才是展示验收证据。
- **部署与恢复。** 在目标架构验证自有三镜像、迁移、管理员初始化、HTTPS、邮件、存储、任务重启和实际创作闭环。备份恢复到隔离环境后核对账号、余额、工程、素材与未完任务；镜像健康、启动成功或只恢复数据库都不能代替业务恢复。
- **容量与发布证明。** 以有代表性工程验证10人同时编辑与全局3/每人1媒体任务限制，分别记录交互/保存/错误、任务排队与供应商耗时，不能以空画布或模拟供应商速度宣称生产容量。所有保留能力通过、例外清楚、公开运营条件和恢复演练满足后，再取得用户验收；源码检查、离线测试、真实调用、部署和用户验收分别记载。

## Out of Scope

- 第一阶段新增产品能力、全站布局重做、替换组件体系、自研替代认证/模型网关/任务队列/账务/素材/编辑器系统。
- 其他AI供应商、个人供应商渠道或本地AI推理兜底；普通媒体加工不在此排除项中。
- 自动启用全部4aion型号，或为了供应商额外API新建原产品没有的模块。
- 未确认的组织租户、团队实时协同、旧工程数据迁移，以及继承旧项目的自定义会话/分享期限、积分赠额、费用补贴或其他策略。
- 网站自动收款作为首期必备目标；现成支付渠道若后续启用，需对应商户配置和验收，不在本次规格发布时执行。
- 删除法定署名、未经授权使用第三方素材/可选组件，或为了更名破坏内部兼容标识。
- 未明确范围及预算的付费测试；本次to-spec仅编写和发布规格，不执行产品改造、部署或新的服务器清理。
- 第二阶段功能细节、多副本高可用或未经验证的无限容量保证。

## Further Notes

本规格在用户确认方案及测试边界后形成；它是未来实施和验收合同，不是产品已完成声明。`ready-for-agent`表示可在依赖和已授权边界内推进任务，不自动提供真实调用预算、商业定价、最终上线或用户验收结论。

已有准备成果：独立工程和分支、Matt技能配置、领域词汇表、ADR-0010、三份调研报告与一期任务依赖。此前已按单独授权停止5个旧转绘应用容器，数据库、存储和数据卷保留；该运维事实不是新工程已部署的证据。源码/文档调查已完成，产品测试、真实模型验收、压测和新部署尚未完成。

后续配置待办：域名与HTTPS入口、SMTP、存储与备份安排、4aion目标账号和有效模型/价格、积分换算与售价、真实验收的模型/次数/预算。账号初始额度、存储限额及其他运营参数按原生配置核对，不在此猜测新数值；遇到阻碍安全运营的缺口在对应任务报告，不静默改变业务策略。密钥和服务器身份文件不写入规格。
