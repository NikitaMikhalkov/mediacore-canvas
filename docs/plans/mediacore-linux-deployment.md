# Mediacore Linux 部署

一期沿用上游 `docker-compose.deploy.yml` 的 PostgreSQL、Redis、迁移、后端、Web 和独立 Agent。源码构建叠加 `docker-compose.build.yml`，后端补装原生媒体处理需要的 FFmpeg/ffprobe，不新增业务模块。

## 当前边界

首次部署按用户要求停用模型。用户随后确认先供内部试用：启用首批文本、图片，每次 1 积分，保留已有视频设置；再补齐示范文件的全部九型号，新增六项每次 1 积分。配置见[原生渠道说明](mediacore-4aion-native-config.md)。此次试用价格有单独授权，不是正式商业售价；商业售价仍待确认。不新增付费测试，由用户在画布试用。公开注册在 SMTP 就绪前关闭，保留原生邮箱验证。

## 运行目录与版本

本工程独立目录为 `/srv/mediacore-yingce`，Compose 项目为 `mediacore-yingce`。其他工程的容器、目录和数据保留。

- `releases/<完整提交 SHA>`：提交的源码及原生 Compose。
- `current`：当前运行版本的链接。
- `.env`：数据库密码、Agent Token、镜像引用和运行配置，仅 root 可读。
- `state/backend`：原生素材及 `.settings-key`；`state/postgres`、`state/redis`、`state/web`：各服务的持久目录。
- `ops`：本次构建记录、镜像内容 ID、私密初始化资料及备份脚本。
- `backups`：数据库、素材、解密设置所需文件和部署配置的常规备份。

首次部署的三个自有镜像由提交 `26cbbe5eb69100da7ed37dabcd6e7223086fbfc0` 构建，以完整 SHA 为独立标签，并记录 Docker 内容 ID。Web 与后端通过 `BUILD_COMMIT`、`BUILD_TIME` 显示构建来源；Agent 使用同一份源码。这是自有镜像部署，不宣称已发布 GHCR digest 版本。上游 Host Updater 未安装，不使用它覆盖本次源码部署。

## 上游更新边界

当前生产源码入口是自有 fork 的 `mediacore/yingce-phase1-20261013` 分支。`upstream` 指向影策官方仓库，仅作为更新来源；fork 默认 `main` 与二开分支分别维护，不能将默认分支等同于已验证的生产版本。应用镜像按自有提交 SHA 部署，Host Updater 未安装，当前没有自动跟随官方版本替换线上服务的机制。

### 更新步骤

1. 核对当前线上各服务的源码提交、镜像、部署配置及工作区未提交改动，保留已有工作；选择明确的上游 tag 或提交 SHA，不将移动的 `latest` 或默认分支当作生产版本。
2. 从当前生产二开源码建立临时升级分支，合并选定上游版本。逐个解决文本冲突并核对下面的二开保留项；自动合并成功不代表行为正确。保留二开提交历史，不用强制推送、重置为上游或整包源码覆盖来完成升级。
3. 只对受影响路径运行必要检查，复用上游测试与原生业务流程，不因升级重做全套验收或自研替代模块。真实 AI 调用必须有适用的费用授权；没有预算时使用离线检查并明确未验证的生成流程。
4. 发布前备份数据库、素材、`.env`、`.settings-key` 和部署配置，保留旧镜像及回退入口；检查上游迁移和初始化逻辑是否改写已有设置。由最终合并提交构建自有镜像，按固定版本发布；源码合并与生产部署分别记录，部署须在用户授权范围内。
5. 发布后检查受影响的原生入口和配置读回，记录自有提交、上游版本、保留或被上游替代的补丁、检查结果与跳过项、备份位置和回退点。区分源码检查通过、部署成功及用户试用确认。

以上步骤仅针对上游升级，不要求普通文案或局部 UI 修改额外建立升级工程、拆票或执行全量测试。

### 二开保留项

- **品牌**：用户可见名称、默认文案及内置 Skill 名称使用 Mediacore；保留原作者、许可证与来源署名。沿用 Skill ID、插件协议、缓存键等内部兼容标识，不为改名破坏历史引用。依据见 [最小复用决策](../adr/0010-mediacore-minimal-fork-and-provider-boundary.md)。
- **4aion**：保留一个渠道下多个模型、每模型原生协议、平台统一密钥与积分策略；保留已关闭的个人渠道、配音/转写及绕过 4aion 的插件开关。以[现有渠道配置](mediacore-4aion-native-config.md)和线上实际设置核对，不恢复旧文档中的模型名或价格。
- **局部修复与界面**：核对 Agent 审批字段投影、生成状态去重、连接器隐藏，以及单渠道模型列表的名称、积分和紧凑选择状态。具体行为与验证边界见[待测试记录](../content/docs/progress/pending-test.mdx)；上游已有等效实现时可移除冗余补丁，记录依据。
- **运行数据**：模型名、价格、启停、品牌外观、账号、积分与素材按当前用户配置保留。升级源码不覆盖 `.env`、`state/` 或 `.settings-key`；内置技能启动同步也属于需检查的配置写入路径。

### 回退与技术保护

旧镜像用于应用回退；数据库迁移需另行判断可逆性。应用回退不等于数据恢复，不直接导入旧库覆盖升级后新增的用户数据。备份目前仅保留于同一服务器，未完成恢复演练，不据此宣称灾难恢复已验证。
