# 优先复用，最小二开，不自研缺失能力

用户选择优先复用已开发能力，以最小原则二次开发：验证原生行为、配置现有能力、做已确认范围内的品牌、玻璃样式和必要局部调整。现有功能满足要求时，以验证证据交付，允许零产品代码变更。

现有机制无法表达的目标，记录原行为、目标差异和可复用选项，作为待决项；不自研缺失业务能力，不另建协议、账务、认证、队列、素材或 Agent 编排系统，也不迁入另一套系统替代复用。费用授权上限、重复提交保护、不可交付退款等产品目标保留，但不因此自动获准新增实现。

这一取舍降低维护面与升级冲突，代价是部分模型和定制规则可能暂不能开放。全站 Mediacore 品牌、玻璃风格以及组件布局不变的要求继续保留。

用户明确要求清理会误导执行的旧规划。已撤回的任务草稿直接移除，重复计划合并到唯一[执行方案](../plans/mediacore-execution-plan.md)；需求保留在正式规格，研究仅保留事实、证据和能力差异，Linear 只记录实际工作及待决项。上游历史设计保留为源码背景，不作为本项目实施清单。
