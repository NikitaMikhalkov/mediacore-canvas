## 决策性结论

1. 上游已有多用户认证、系统渠道、持久任务、素材、积分、兑换码和管理能力；先验证和配置，不另建同类系统。
2. 4aion 有官方文本、图片、视频、素材与存储文档；逐模型参数、实际账户价格、音频字幕合同仍需补证。公开目录 87 个条目不等于全部可用或免费。
3. 品牌优先使用原生站点与 Agent 外观配置，再补默认/降级硬编码；保留许可证和内部兼容标识。
4. 成片导出依赖 FFmpeg，当前后端生产镜像需补齐；原生字幕依赖 Whisper，与仅限 4aion 冲突。按用户决定，不支持的 AI 功能可明确关闭后首期上线。
5. 生产需自有 web/backend/agent 三镜像来源闭合、受控管理员初始化、双用户隔离和备份恢复验证，不能以 Compose 健康替代完整验收。

本轮完成静态源码/一手文档调研、独立工作目录与 skills 配置、用户决策记录、Linear 任务登记及目标服务器只读基础检查。未运行产品测试或完整构建，未做真实模型/付费调用，未完成产品改造、部署、压测或上线验收。报告中的原生实现和测试文件都不是“已通过”结论。

服务器只读检查为 Ubuntu 24.04、x86_64、4核、约7.4 GiB内存，已有 Docker/Compose 与较多工作负载；检查时可用内存约1.6 GiB、磁盘剩余约155 GiB。它是一次观测，不是容量保证。SSH 地址、身份文件与实际用户凭据不写入仓库。

用户随后明确授权停止旧 Mediacore 转绘 Docker。按 Compose 发布目录与容器归属确认后，停止了旧转绘 web、API、worker、Agent provisioner 和独立转绘服务，共5个应用容器；确认均为 exited，未删除容器、镜像或数据卷，数据库/存储与其他工程服务保留。停止后 available 内存约2.6 GiB；其中 API 和 provisioner 退出码137，后续恢复旧转绘前需检查未完成任务。这次停止是已授权的独立运维动作，不代表新工程已经部署。
